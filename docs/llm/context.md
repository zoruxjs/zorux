# Zorux — LLM Context

## Core Architecture

Zorux is a YAML-first full-stack framework. A single `app.yaml` defines models, auth, database, cache, email, plugins, and real-time config. The framework compiles this into a complete application at runtime.

**Runtime:** Bun + Hono
**Default DB:** SQLite (via `bun:sqlite`)
**Admin UI:** DaisyUI 5 + Tailwind CSS 4 (compiled via `build:css`)
**Auth:** JWT-based, 35 OAuth providers, WebAuthn, 2FA TOTP

## File Structure

```
project/
  app.yaml              ← Single source of truth (EDIT THIS)
  actions/*.ts          ← Custom API handlers
  jobs/*.ts             ← Background jobs
  plugins/*.ts          ← Custom plugins
  web/pages/*.tsx       ← Public pages (auto-loaded by route)
  seed.ts               ← Database seed script
  .zorux/
    manifest.json       ← Generated contract (zorux inspect --json)
    context.md          ← Generated context (zorux context)
```

## app.yaml Quick Reference

```yaml
name: my-app
type: fullstack          # api | fullstack | web | mobile
database:
  provider: sqlite       # sqlite | postgres | mysql | mongodb | supabase | d1
auth:
  model: User
  registration: open     # open | invite | closed
  roles: [admin, member]
  organization:
    enabled: true
    roles: [owner, admin, member]
  social:
    google:
      clientId: ${GOOGLE_CLIENT_ID}
      clientSecret: ${GOOGLE_CLIENT_SECRET}
models:
  Post:
    fields:
      title: string required max:200
      body: text required
      status: string enum:draft,published
      author: User
    timestamps: true
    policies:
      list: "*"
      create: authenticated
      update: owner
      delete: admin
    hooks:
      beforeCreate: actions/validate-post.ts
      afterCreate: actions/notify-subscribers.ts
    softDelete: true
    scoped: true          # Multi-tenant
cache:
  provider: memory       # memory | redis | upstash | memcached | dynamodb | kv | do
email:
  provider: sandbox      # sandbox | resend | sendgrid | smtp
realtime:
  enabled: true
forms:
  subscribe:
    title: Newsletter
    model: Subscriber
    fields: [email, name]
    button: Subscribe
    honeypot: true
plugins:
  - my-plugin
```

## Editable vs Generated

**Edit these (user-authored):**
- `app.yaml` — models, auth, plugins, config
- `actions/*.ts` — custom API handlers
- `plugins/*.ts` — custom plugins
- `web/pages/*.tsx` — public pages
- `jobs/*.ts` — background jobs

**Do not edit directly (generated or derived):**
- `.zorux/manifest.json` — generated by `zorux inspect --json`
- `.zorux/context.md` — generated by `zorux context`
- Admin CRUD routes — derived from YAML models
- API routes — derived from YAML models
- Database schema — derived from YAML models
- OpenAPI spec — derived from YAML models

## Key Patterns

### Adding a model
1. Edit `app.yaml` → add under `models:`
2. Run `zorux db migrate` to create table
3. API routes, admin CRUD, OpenAPI docs auto-generated

### Adding a custom action
1. Create `actions/my-action.ts`
2. Export named handlers with policy
3. Accessible at `POST /api/actions/my-module/my-handler`

### Adding a public page
1. Create `web/pages/pricing.tsx`
2. Auto-route: `GET /pricing`
3. Must export a function component returning HTML string

### Override generated behavior
1. Create `plugins/override.ts`
2. Use `onRoutes(app)` hook to register routes before core
3. Routes registered by plugins override core CRUD routes

## Maturity Levels

- **✅ Stable**: API, CRUD, SQLite, Admin, Auth, OpenAPI, Cache, DB migrations, CLI new/dev/seed/test
- **🧪 Beta**: GraphQL, Webhooks, Jobs, Plugins, Feature Flags, Deploy
- **🔬 Experimental**: Mobile (Expo), Desktop (Tauri), Payments, Multiple DB providers (postgres, mysql, mongodb)
