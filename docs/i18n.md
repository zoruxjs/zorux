# i18n (Internationalization)

<!-- maturity: 🔬 Experimental -->
> **🔬 Experimental** — This feature is in early development — not recommended for production


Zorux includes built-in internationalization with locale detection, translation files, and a `t()` function.

## Configuration

```yaml
i18n:
  defaultLocale: en             # Default locale
  locales: [en, pt-BR, es, fr]  # Supported locales
  cookieName: lang              # Cookie name for locale
```

## Translation Files

Translation files are JSON files in the `locales/` directory:

```
locales/
├── en.json
├── pt-BR.json
├── es.json
└── fr.json
```

### File Format

```json
{
  "common": {
    "save": "Save",
    "cancel": "Cancel",
    "delete": "Delete",
    "edit": "Edit",
    "create": "Create",

  "auth": {
    "login": "Login",
```

## t() Function

```typescript
function t(key: string, vars?: Record<string, string | number>, locale?: string): string
```

### Basic Usage

```typescript
t("common.save")           // "Save"
t("auth.login")            // "Login"
t("errors.notFound")       // "Not found"
```

### With Variables

```typescript
t("posts.count", { count: 42 })
// Translation: "{count} posts"
// Result: "42 posts"
```

### With Locale Override

```typescript
t("common.save", {}, "pt-BR")  // "Salvar"
```

### Fallback Behavior

1. Look up key in current locale
2. If not found, look up in default locale
3. If still not found, return the key itself

## Locale Detection

Priority order:

1. **`lang` query parameter** — `?lang=pt-BR`
2. **`lang` cookie** — `Cookie: lang=pt-BR`
3. **`Accept-Language` header** — Browser language preference
4. **Default locale** — From `i18n.defaultLocale`

### Query Parameter

```
http://localhost:3000/?lang=pt-BR
http://localhost:3000/admin?lang=es
```

### Cookie

```
Cookie: lang=pt-BR
```

### Accept-Language Header

```
Accept-Language: pt-BR,pt;q=0.9,en;q=0.8
```

## Locale Detection Middleware

The middleware runs on every request:

1. Checks `lang` query parameter
2. Checks `lang` cookie
3. Parses `Accept-Language` header
4. Sets locale on request context
5. Sets `Content-Language` response header

The admin UI uses the `t()` function for all strings. Switching locale updates all UI text.

## Adding a New Locale

1. Create `locales/{locale}.json`
2. Copy keys from `en.json`
3. Translate values
4. Add locale to `i18n.locales` in `app.yaml`

```yaml
i18n:
  defaultLocale: en
  locales: [en, pt-BR, es, fr, de]
```

## Best Practices

1. **Use nested keys** — `auth.login` instead of `authLogin`
2. **Keep keys consistent** — Same key structure across locales
3. **Use variables** — `{count}` instead of string concatenation
4. **Translate everything** — All user-facing strings
5. **Test all locales** — Verify each locale renders correctly
6. **Handle missing keys** — Fallback to default locale gracefully
